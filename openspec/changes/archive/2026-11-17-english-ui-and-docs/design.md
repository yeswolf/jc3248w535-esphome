# Design

## Context

See `proposal.md` - Why. The on-device UI is drawn with an 8x16 bitmap font that covers
ASCII and Cyrillic. Several existing Russian strings use punctuation the font does not
contain (U+2026 ellipsis, U+00D7 multiplication sign, U+2022 bullet), so those glyphs
already rendered as `?`. The English rewrite removes that class of bug by using ASCII
punctuation where the font has no glyph.

## Goals / Non-Goals

**Goals:**

- One language for the UI, web pages, Home Assistant entities and documentation.
- Keep the UI within the existing 480x320 layout; no coordinate changes.
- Preserve Cyrillic glyphs so Cyrillic file names on the SD card still render.

**Non-Goals:**

- Do not change playback, storage, USB, Wi-Fi or OTA behavior.
- Do not remove the Cyrillic font glyphs.
- Do not translate vendor documents under `docs/vendor/`.

## Decisions

### UI strings

All strings are translated in place. Lines that were wider in Russian are shorter in
English; the existing x/y coordinates and button rectangles remain valid. Punctuation
is limited to characters present in the font: `...` instead of `…`, `x` instead of `×`,
`|` instead of `•`.

### Entity names and IDs

Entity names are translated literally, for example the file selector, the sleep
switch and the firmware update entity. Home Assistant derives entity IDs from the
device name and the entity name, so IDs such as
`select.guition_jc3248w535_3_5in_ips_file` replace the Russian transliterations. The
dashboard example is rewritten with the new IDs and English labels.

### Font

The glyph data is unchanged. Only the generated comments lose the character text and
keep `// U+XXXX`, so the source stays ASCII. `tools/make_font.py` emits the same format
and its self-check uses numeric code points instead of Cyrillic literals.

### Screenshots

The previews are regenerated by the same renderer from the translated strings, using the
real font data and layout constants.

## Risks / Trade-offs

- Existing Home Assistant automations that reference the old entity IDs must be updated.
  This is recorded as a breaking change in the proposal; the dashboard example and README
  carry the new IDs.

## Migration Plan

1. Translate strings, entity names and docs.
2. Regenerate screenshots and rebuild the firmware.
3. Replace the release assets.
4. Force-push the squashed release commit.

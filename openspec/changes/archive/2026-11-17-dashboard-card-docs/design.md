# Design

## Context

The full card in `esphome/dashboard_card.yaml` targets the device log iframe and every
diagnostic entity, so it is large. A second card should cover the common controls
without duplicating the diagnostics block.

## Goals / Non-Goals

**Goals:**

- A compact, copy-pasteable card for everyday playback control.
- Links from both READMEs to the full and compact cards.
- No personal IP addresses, room names or entity IDs in the committed cards.

**Non-Goals:**

- Do not change the firmware, entity names or entity IDs.
- Do not change the full card's layout.

## Decisions

- The compact card keeps a `media-control` card, an entities card with file, now
  playing, sleep and brightness, a four-button transport row and a three-button row for
  slideshow, refresh and browser.
- The compact card has no iframe, so it needs no device address at all. The full card
  keeps the documentation address `192.0.2.10` with a note to replace it.
- Entity IDs follow the English names generated by the current firmware.

## Risks / Trade-offs

- Entity IDs depend on the Home Assistant device name. Both cards say to adjust them if
  the installation generated different IDs.

## Migration Plan

1. Add the compact card.
2. Link both cards from the READMEs.
3. Commit into the existing single release commit and push.

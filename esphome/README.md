# ESPHome / Home Assistant build

This directory carries the ESPHome firmware for the Guition **JC3248W535**
(ESP32-S3-WROOM-1 N16R8). It compiles the external component in
`components/jc3248_media/`, which provides the on-device file browser, touch UI,
MJPEG player and USB mass-storage drive. On top of that, ESPHome exposes the
player to Home Assistant.

## Entities

| Entity name | Type | What it does |
|---|---|---|
| **File** | select | Dropdown of every playable file on the card (recursive, sorted). Choosing a file starts playback immediately. |
| **File to delete** | select | Independent selector: choosing a file here does not start playback. |
| **Delete file** | button | Deletes the file chosen in **File to delete** from the card. Deletion is permanent. |
| **Play** | button | Plays the selected file, or the first file when nothing is selected. |
| **Slideshow** | button | Plays every playable file in order, starting at the selected one and looping. Still images are held for 10 seconds. |
| **Previous** / **Next** | button | Plays the previous / next file in the same sorted playlist. Works while a video is playing. |
| **Stop** | button | Stops playback and returns to the browser. |
| **Sleep** | switch | Sleeps the device: playback stops and the backlight is switched off. The panel and CPU stay in their normal state, and Wi-Fi and the API stay up so Home Assistant can wake it. |
| **Brightness** | number (0–100) | Backlight PWM level. 0 % is fully dark. |
| **Screen colour** | RGB light | Turning it on fills the panel with the picked colour. Turning it off, or touching the screen, returns to the browser. |
| **Now playing** / **Playing** | text/binary sensor | The path currently being played and whether playback is active. |
| **Refresh list** | button | Rescans the card without replugging it. |
| **Show browser** | button | Leaves colour mode and shows the file browser. |
| **Reboot** | button | Restarts the ESP32 through the ESPHome restart action. Works while the API is responsive and does not need a power cycle. |
| **Firmware update** | update | Device-pull OTA: reads the manifest from `firmware_manifest_url`, compares versions and installs `firmware.ota.bin` from Home Assistant. |

Entity IDs are generated by Home Assistant from the device name and these
names; rename them in the Home Assistant UI if your automations expect
different IDs.

Ready-to-paste dashboard cards: [`dashboard_card.yaml`](dashboard_card.yaml)
(full) and [`dashboard_card_mini.yaml`](dashboard_card_mini.yaml) (compact).

On the device's touch browser, holding a file row for about 0.7 seconds opens a
delete confirmation dialog. Confirming removes the file from the card
permanently; directories are not deleted.

## Build and flash

```sh
cd esphome
cp secrets.example.yaml secrets.yaml   # fill in Wi-Fi, API key, upload login
esphome compile jc3248w535.yaml
```

The checked-in build was made with ESPHome 2026.10.0 (Python 3.12, ESP-IDF
5.5.6); any recent ESPHome release that supports ESP-IDF 5.5 should work.

First flash over USB (the runtime USB port belongs to the mass-storage device,
so the board has to be put into download mode):

1. Hold **BOOT**, press and release **RST**, release **BOOT**.
2. Unplug and replug the USB-C cable.
3. Flash the merged image at offset 0:

```sh
esptool.py --chip esp32s3 -p /dev/ttyACM0 -b 460800 \
  write_flash 0x0 \
  .esphome/build/guition-jc3248w535/build/firmware.factory.bin
```

After the first flash, update over the network:

```sh
esphome run jc3248w535.yaml
```

Home Assistant discovers the device through the ESPHome integration once the
`api:` key is set. The API key, Wi-Fi credentials and upload login live in
`secrets.yaml`, which is gitignored.

## OTA updates from Home Assistant

Three paths are available. The first one works entirely through the device
update entity in Home Assistant and does not need the ESPHome dashboard.

### 1. Device-pull update entity (`update: platform: http_request`)

The firmware reads a JSON manifest, compares its `version` with the installed
`project.version` (`fw_version` in the YAML), and — when a newer version is
published — shows an update entity in Home Assistant. Pressing **Install**
makes the device download `firmware.ota.bin` and flash it itself.

Build and publish a new version:

```sh
cd esphome
# bump fw_version in jc3248w535.yaml, e.g. 1.0.1
esphome compile jc3248w535.yaml

# destination = Home Assistant's /config/www/jc3248w535
../tools/publish_ota.sh \
  .esphome/build/guition-jc3248w535/build/firmware.ota.bin \
  /config/www/jc3248w535 \
  1.0.1
```

`publish_ota.sh` copies `firmware.ota.bin`, computes its MD5 and writes
`manifest.json` in the ESP-Web-Tools format. Home Assistant serves
`/config/www/` at `/local/`, so the manifest URL is:

```
http://<home-assistant>:8123/local/jc3248w535/manifest.json
```

Put that URL into `secrets.yaml` as `firmware_manifest_url` and rebuild once.
The HTTP request is plain HTTP (`verify_ssl: false` in the YAML); use an HTTP
URL or provide a CA certificate if Home Assistant is HTTPS-only.

Notes:

- Use `firmware.ota.bin`, not `firmware.factory.bin`.
- The manifest version must be **greater** than the installed `fw_version`.
  Bump both together.
- The device can be in the sleep state: Wi-Fi and the API stay up, so it can
  still download and flash the update.
- The update entity polls every hour; `update.install` can also be called from
  an automation or a dashboard button.
- This mechanism needs the *current* firmware (with the update entity) to be
  installed once manually or through one of the other two paths.

### 2. ESPHome Dashboard update entity

If Home Assistant runs the ESPHome add-on (or an external dashboard connected
to Home Assistant), the ESPHome integration adds a firmware update entity for
each device. It is **disabled by default**; enable it under
**Settings → Devices & services → Entities** (filter for disabled entities).
Pressing **Install** compiles the YAML on the dashboard and uploads it over
OTA. The dashboard also has a normal **Install** button in its own panel.

The dashboard mainly reports ESPHome *version* updates; after changing only
your YAML, use the dashboard's Install button or call `update.install` on the
entity to force a recompile and upload.

### 3. Native ESPHome OTA

`ota: platform: esphome` is also enabled, so `esphome run jc3248w535.yaml`
from a machine on the same network uploads directly. This is the easiest path
for local development.

## Uploading files from Home Assistant

The firmware runs a small HTTP server on port **8080**. Basic authentication
is optional and off by default (`upload_username` / `upload_password` empty):

* `GET /` — a browser page with a file picker, progress bar and the list of
  files on the card;
* `GET /logs` — log-only page with the last 160 device log lines;
* `GET /api/logs?since=<seq>` — incremental log text for the page;
* `POST /upload?name=<file>` — raw request body written to `/sdcard/<file>`;
* `GET /api/files` — JSON playlist;
* `GET /api/status` — JSON playback/sleep/colour state.

The browser page accepts JPEG and PNG photos and converts them to a
480x320 JPEG in the browser before uploading, so phone photos work without
manual resizing. The direct `POST /upload` path does no conversion: a photo
sent by `shell_command` or `curl` must already be 480x320 JPEG.

A selected photo is decoded once per loop and stays on screen until Stop,
Next, another file, or sleep. In the slideshow a photo is held for 10 seconds
before the next file, while videos keep their own duration.

The simplest Home Assistant path is a dashboard card that opens the page:

```yaml
type: iframe
url: http://guition-jc3248w535.local:8080/
aspect_ratio: 60%
```

If Home Assistant is served over HTTPS, browsers block a plain-HTTP iframe;
open `http://guition-jc3248w535.local:8080/` directly, or use a web-page card that
proxies it.

For automations, upload a file that already lives on the Home Assistant host:

```yaml
shell_command:
  jc3248_upload: >-
    curl -sS --fail
    --data-binary @"{{ file }}"
    "http://{{ host }}:8080/upload?name={{ name | urlencode }}"

script:
  jc3248_upload_video:
    alias: Upload a video to JC3248W535
    fields:
      file:
        description: Path on the Home Assistant host, e.g. /media/videos/clip.avi
      name:
        description: Name on the card, e.g. clip.avi
      host:
        description: Device host or IP
        default: guition-jc3248w535.local
    sequence:
      - service: shell_command.jc3248_upload
        data:
          file: "{{ file }}"
          name: "{{ name }}"
          host: "{{ host }}"
```

If you set `upload_username` / `upload_password`, add
`-u "{{ user }}:{{ password }}"` to the `curl` line and pass those fields.

Only a bare file name with a playable extension (`.avi`, `.mjpeg`, `.mjpg`,
`.mjpe`, `.jpg`, `.jpeg`) is accepted. The body is written to the card root;
an existing file with the same name is replaced. The upload is refused while
the card is owned by a USB host, and the configured body limit is 64 MiB
(`max_upload_mb`).

After an upload, the device rescans the card and asks the ESPHome API clients
to reconnect. ESPHome sends a select's option list only with
`ListEntitiesSelectResponse`, so this short reconnection is what makes the new
file appear in the Home Assistant dropdown without reloading the integration.
The device becomes briefly unavailable during the reconnect.

## Sleep, brightness and colour

* **Sleep** is not deep sleep: the device must stay on Wi-Fi to be woken from
  Home Assistant. The switch stops playback and turns off the backlight. The
  panel stays on and the CPU clock is not changed: DISPOFF/DISPON and runtime
  frequency changes proved unreliable on this panel and left the device hung
  after wake in 1.0.5. The backlight is the main consumer, so the saving stays
  meaningful while wake is instant and reliable. True deep sleep would drop
  the network and could not be woken remotely.
* The **brightness** number is the backlight level (LEDC PWM on GPIO 1). It is
  independent of the screen-colour light.
* The **colour light** sets the RGB fill colour; its own brightness slider
  scales that colour. The backlight stays at the number entity's level.

## Logs

The upload server on port **8080** also serves a log-only page at `/logs`; it
shows the recent ESPHome log lines and has Pause/Clear buttons. The dashboard
card embeds exactly this page. Open it from Home Assistant's device page with
the **Visit** link (the upload page links to the logs), or directly:

```
http://guition-jc3248w535.local:8080/logs
```

The log ring holds the last 160 lines. There is no ESPHome web UI or admin
panel on the device.

To forward device logs into Home Assistant's own **Settings → System → Logs**,
enable the ESPHome integration option **Subscribe to logs from the device**
(Configure on the integration entry). The forwarded level follows the
`homeassistant.components.esphome.manager` logger; set it to `INFO` to include
normal log lines, otherwise only warnings and errors are forwarded.

The command-line viewer remains available:

```sh
esphome logs jc3248w535.yaml --device 192.0.2.10
```

`192.0.2.10` is a documentation address; replace it with the device IP.
It reads the API key from `secrets.yaml` and needs the ESPHome CLI with the
ESP-IDF 5.5.6 toolchain installed.

## Diagnostics

The firmware publishes these diagnostic sensors; the dashboard card has a
"Diagnostics" section with the same values:

| Sensor | Unit | Source |
|---|---|---|
| ESP temperature | °C | ESP32-S3 internal die temperature (`internal_temperature`), not ambient |
| CPU load | % | FreeRTOS per-task run-time counters, delta over 10 s |
| Free memory | B | Internal heap free size |
| Minimum free memory | B | Lowest internal heap free size since boot |
| Largest memory block | B | Largest free internal heap block |
| Memory fragmentation | % | Internal heap fragmentation |
| Free PSRAM | B | Free PSRAM |
| Loop time | ms | Main loop time from the `debug` component |
| CPU frequency | Hz | Current CPU frequency |
| WiFi RSSI | dBm | Wi-Fi signal strength |
| Uptime | s | Uptime since boot |

CPU load needs `CONFIG_FREERTOS_GENERATE_RUN_TIME_STATS: "y"` in the
`sdkconfig_options`; the default ESP timer is the counter source. The load is
measured across both cores, so it is a percentage of the total CPU capacity.

## Layout

```
jc3248w535.yaml       ESPHome configuration
secrets.example.yaml  template for secrets.yaml
idf_components/       vendored IDF components (do not compile twice)
  esp_lcd_axs15231b/  AXS15231B QSPI panel/touch driver
  esp_tinyusb/        esp_tinyusb 2.4.0 with the synchronous card-write patch
```

The ESPHome component itself lives in `components/jc3248_media/`. Board
schematics, datasheets, the vendor documentation and factory firmware are
archived in [`../docs/`](../docs/README.md).
